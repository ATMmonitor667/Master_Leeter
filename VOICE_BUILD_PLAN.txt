1. GOAL AND DEFINITION OF DONE
==========================================================================================

GOAL
  A voice interview where, once the interviewer has decided to speak, the candidate hears it
  about as fast as a person across a table would answer -- while keeping the product's core
  property: the interviewer stays silent by default and never talks over someone mid-thought.

  The research paper's key finding, restated: the interviewer's slowness came from HOW its
  silence was implemented, not from the silence itself. "Reluctant" was being expressed as
  "slow". The fix is to make the decision well-informed and fast, and to make execution of
  a decision nearly instant -- without changing how often it decides to speak.

MEASURED DEFINITION OF DONE (all must hold on recorded human sessions, P10)
  D1  Response latency = first audible interviewer sample minus the candidate's backdated
      quiet onset, measured in the browser by the V0 ledger:
        - MOCK, authored utterance after a finished statement: p50 <= 800 ms, p95 <= 1400 ms
        - Direct question (floor-yielded intent):               p50 <= 800 ms, p95 <= 1400 ms
        - Stretch target (needs fast provider transcripts, see section 4): p50 <= 600 ms
  D2  Unwanted interruption rate < 1 material interruption per 30-minute MOCK session
      (CLAUDE.md quality metric), judged by human review of the recorded session.
  D3  Missed-response rate: 0 clear questions left unanswered across the acceptance sessions.
  D4  Backchannel false-stop: a candidate "mm-hm" during interviewer speech does not cancel
      a pre-rendered utterance (spot-checked, >= 4 of 5 attempts).
  D5  TTS fidelity: every cached line passes automatic render verification (P3.3); spot
      listening finds no spoken style direction and no altered word.
  D6  All automated suites green: typecheck, API, web, contracts, sim, eval thresholds,
      production build, check:sorted, check:env, check:bundle.
  D7  Replay determinism preserved: replay.test.ts and the new replay tests pass; logs
      written before this work replay to identical decisions.

  Report D1 and D2 TOGETHER, always. A system reaches 100 ms by interrupting constantly and
  0% interruptions by never speaking; either number alone is meaningless (paper, section 8).

3. INVARIANTS THAT MUST SURVIVE EVERY PHASE
==========================================================================================

From CLAUDE.md (numbers match CLAUDE.md) and ADR-001:
  I1  Application-controlled response creation. Turn detection is never permission to
      speak. The Response Gate is the only authority. STAY_SILENT is the default.
  I2  The problem statement is never rendered as text. Authored wording never crosses to
      the browser as TEXT. (Audio of an authorized utterance may -- it always did.)
  I3  Clarifications come from canonical scenario facts; the model never invents.
  I4  Sessions pin an immutable scenario version.
  I7  Candidate speech is data, not policy.
  I8  The event log is append-only; decisions are a function of the log (replay).
  I9  Deterministic rules run before model reasoning in the gate.
  I10 No raw audio retention by default. (Derived prosody numbers are not audio, but treat
      them as personal data for redaction.)

Plan-specific invariants (each phase must keep these true):
  V-a  A decision-affecting value is either in the log or a pure function of the log.
       Live-only optimisations (speculation, caches, prewarm) may change WHEN a decision is
       made, never WHAT it is.
  V-b  No prosody, no cache, no speculation => behaviour identical to main. Every new
       mechanism degrades to today's behaviour, not to a guess.
  V-c  Nothing new can make the interviewer speak. New inputs can only change how long the
       gate waits, or how fast an already-authorized utterance is executed.
  V-d  Fail toward yielding the floor: when uncertain whether the candidate took the floor,
       the interviewer goes quiet.
  V-e  Browser-supplied numbers are validated server-side; out-of-range values are dropped,
       not clamped.

4. THE LATENCY MODEL
==========================================================================================

Clock starts at t=0, the candidate's last voiced sample (VAD's backdated quiet onset).

TERMS
  H     VAD hangover before SPEECH_END is declared           350 ms today (config)
  T_f   provider delay from activityEnd to the final input    UNMEASURED (P1 measures it)
        transcription reaching the browser
  N_up  browser -> API over the app WebSocket                 ~20-60 ms
  C     classifier call (Gemini flash-lite, structured JSON)  ~300-800 ms (code comment)
  R     silence the policy requires before a non-question     MOCK 2400 ms today
        turn may be answered
  S     execution: decision -> first audible sample           see below
  L     playback lead (clipping guard)                        60 ms (playback.ts)

EXECUTION S TODAY (model path)
  ACTION push + model turn -> tool call + relay + model turn -> first audio
  ~ 30-80 + 400-900 + 50-150 + 644-1958 = ~1.1 - 3.0 s

THE CRITICAL-PATH FORMULA ON MAIN (derived from runtime.ts, see defect D-4)
  statement turn:  t = H + T_f + N_up + C + max(0, R - (H + T_f)) + 25 + S
  question turn:   t = H + T_f + N_up + C + S          (floor-yielded: R not applied)
  NOTE: the paper said C is "absorbed into the silence hold". It is NOT: holdForSilence()
  computes the wait from timestamps taken BEFORE the classifier returned, then starts the
  timer AFTER it returned, so C is added on top. (Defect D-4, fixed in P2.4.)

TARGET AFTER THIS PLAN
  statement turn:  t = max(H + T_f + N_up + C', R') + 25 + S'
  question turn:   t = H + T_f + N_up + C' + S'
  where
    R'  MOCK with confident prosody = 577 ms (Appendix B)     [P4]
    C'  ~0 when speculation hits, else C                      [P5]
    S'  ACTION push + N_down + L ~ 10 + 40 + 60 = ~110 ms      [P3: head rides on ACTION]
    and C is absorbed into the hold for statements             [P2.4]

  Worked budgets (MOCK, N_up = N_down = 40 ms):
                           T_f=150ms   T_f=300ms   T_f=700ms
    statement, spec hit       ~710        ~825        ~1225   (max(H+T_f+N_up, 577)+25+110)
    question,  spec hit       ~650        ~800        ~1200
    question,  spec miss (C=500)  ~1150   ~1300       ~1700

  Therefore:
    - After P2-P5, T_f is the dominant unknown and the floor. P1 measures it FIRST.
    - Speculative classification (P5) is required, not optional, for questions to be fast.
    - Trimming leading silence from TTS renders (P3.3) and a tighter first-chunk lead
      (P3.8) are small, free wins inside S'.
    - The 200 ms human mode is out of reach without predicting turn ends BEFORE the pause
      (full duplex); this plan targets the human MEAN (345-456 ms, Brady 1968), and the
      realistic result is 650-850 ms p50 if T_f <= 300 ms.

5. DEFECTS FOUND ON MAIN WHILE PLANNING (FIX BEFORE MAKING IT FASTER)
==========================================================================================

These come from reading main @ ec8407a. Each must be CONFIRMED by a failing test before it
is fixed (P2). Making endpointing faster without fixing them makes them worse.

D-1  Every provider transcript chunk is judged as a whole turn.
     page.tsx forwards each `inputTranscription` as its own SPEECH_FINAL; runtime.ts
     evaluateTurn() classifies that fragment alone and "a new turn supersedes any turn
     still waiting on silence". If Gemini sends several chunks per utterance (the API
     documents transcriptions as incremental; P1 confirms), the gate sees "because lookups
     are constant time" without "I'd use a hash map", and the mid-thought veto reads the
     wrong tail.

D-2  No "candidate is speaking right now" rule.
     `candidateSpeechStarted` means "has spoken since the last decision", not "is speaking
     now". A final chunk arriving while the candidate is still talking (transcription runs
     during speech) has `silenceMs === undefined` (SPEECH_STARTED nulls it), and
     estimateTurnCompletion() then judges on the transcript alone. A complete-looking
     fragment, or any floor-yielded intent, can therefore authorize speech while the
     candidate is mid-sentence. Suspected interruption source.

D-3  A turn judged without timing is never re-evaluated.
     holdForSilence() returns immediately when silenceMs is undefined. If the final chunk
     arrived before SPEECH_STOPPED and the verdict was STAY_SILENT, nothing re-judges the
     turn after the candidate stops. Suspected missed-response source.

D-4  Silence at re-evaluation mixes two clocks, and re-evaluation happens only once.
     lastSpeechStoppedAtMs comes from the CLIENT (SPEECH_STOPPED.occurredAt is the VAD time
     the browser supplied); the SILENCE_ELAPSED timestamp is SERVER time. reevaluate()
     subtracts one from the other, so client/server clock skew is added to the measured
     silence. If the client clock is ahead, the re-judged silence is too short, the turn is
     held again, and since holdForSilence() only runs on attempt 0, it is never answered.
     Also (section 4) the classifier time is added to, not absorbed by, the hold.

D-5  get_probe_wording speaks the NEXT variant.
     runtime.realize() selects the wording with useCount, then increments
     probeUseCounts[probe.id]. tools.ts probeWording() then selects with the incremented
     count, so the model is handed a different variant than the one realized and logged.
     (Also recorded in V0_V7_REIMPLEMENTATION.md.)

D-6  Hints have no wording on the model path.
     instructionFor(GIVE_HINT_L1/L2) says "Say only the wording you are given", but no tool
     returns hint text. A model-spoken hint must improvise -> leakage risk. (Pre-rendered
     audio avoids this for cached hints; the model fallback still needs a fix.)

D-7  Model audio after a local barge-in can restart the interviewer.
     After onBargeIn stops playback, model audio chunks still in flight are enqueued again by
     onModelAudio. (Recorded as fixed in V0_V7_REIMPLEMENTATION.md on the other machine;
     not fixed on this main.)

D-8  PlaybackScheduler.release() lets a stale source touch the cursor after stop().
     (Same record.) Harmless today, matters once completion is driven by the queue draining.

6. PHASE OVERVIEW AND ORDER
==========================================================================================

  P0  Workspace preparation and baseline                 no behaviour change
  P1  Measure first (V0 ledger + provider probe)          no behaviour change
  P2  Turn integrity (D-1..D-8)                          correctness, some latency
  P3  Pre-rendered authored speech (V3/V3b)              -1.0 to -3.0 s execution
  P4  Prosodic turn-end prediction (V2)                  -1.8 s on statements (MOCK)
  P5  Speculative classification (V4)                    -0.3 to -0.8 s
  P6  Hangover decision (V1)                             +/- 150 ms, data-driven
  P7  Presence and barge-in (V5 + V7)                    perceived naturalness
  P8  Sim / eval / review integration                    guards the numbers
  P9  Docs and records
  P10 Human acceptance and tuning (with the owner)

Why this order:
  - P1 before everything: the paper's budget has an unmeasured term (T_f) that decides
    whether P6 matters and how far P5 can go.
  - P2 before P4: prosody shortens the wait; D-1..D-4 turn a short wait into interruptions
    and missed responses.
  - P3 before P4: P3 does not touch any decision boundary and removes the most time with the
    least risk (paper: "if only one can be done, V3 is the cheaper and the safer").
  - P5 after P4: once the hold shrinks to ~577 ms, the classifier becomes the bottleneck.

11. P4 -- PROSODIC TURN-END PREDICTION (V2)
==========================================================================================

Core idea: "I'll use a hash map." (finished) and "I'll use a hash map..." (continuing) are
the same string at the pause but not the same audio. The finished one falls in pitch,
lengthens its last syllable and trails off in energy; the continuing one holds a level pitch
and stops at full volume. Measure that and let it move the silence window.

P4.1  Predictor (apps/web/lib/turn-predictor.ts + test; reuse the draft as-is)
        TurnEndPredictor interface { id; push(frame, sampleRate, atMs); estimate(atMs);
        reset() }, NullTurnEndPredictor, ProsodicTurnEndPredictor:
          - per 20 ms frame: dBFS and F0 by normalized autocorrelation on a frame decimated
            to 8 kHz (DC removed; lags for 70-400 Hz; voiced if peak >= 0.32)
          - estimate(atMs) reads the 800 ms tail ENDING at the backdated quiet onset:
            terminal pitch slope (semitones/s, least squares), final lengthening (final
            voiced run / median run), terminal energy slope (dB/s)
          - score terms (PROSODY_WEIGHTS, exported, tunable):
              falling <= -2 st/s: +0.9 * min(1, -slope/6)
              rising  >= +3 st/s: +0.7 * min(1, slope/8)       (a question yields)
              level   otherwise:  -1.0 * (1 - min(1, |slope|/3))
              lengthening > 1.15: +0.8 * min(1, (r-1.15)/0.85)
              energy <= -6 dB/s:  +0.6 * min(1, -decay/25)
              energy >= -1 dB/s:  -0.7   (stopped at full volume)
              probability = sigmoid(1.6 * score)
          - confidence = clamp((voiced - 8) / 8) over voiced tail frames; 0 below 8 voiced
            frames -> exactly "no evidence".
        Measured cost on the other machine: ~0.05 ms per frame.
  TEST  The 17 draft tests (falling -> finished, level -> continuing, rising -> yielded,
        confidence 0 for short/silent/noise, semitone invariance across registers, slope
        recovery within 2%).

17. P10 -- HUMAN ACCEPTANCE AND TUNING PROTOCOL (WITH THE OWNER)
==========================================================================================

Sessions (owner runs them; the implementing session prepares and reads the output)
  S1  MOCK, headset microphone, quiet room, 30 min, NORMAL tone
  S2  MOCK, laptop microphone, some background noise, 30 min
  S3  LEARNING or STRICT, 20 min, EXTRA_NICE or MEAN tone (exercises tone renders)
  Raw audio is not retained (I10). The ledger, decisions and transcripts are enough.

After each session
  1. pnpm review -- <session-id>  -> TSV + latency summary.
  2. The owner marks every interviewer turn in the TSV `judgment` column:
     OK | INTERRUPTED_ME | TOO_SLOW | WRONG_MOMENT | NO_ANSWER.
  3. Compute: response latency p50/p95 by action and by source; material interruptions per
     30 min; missed responses; speculation hit rate; cache coverage; backchannel
     false-stops (owner tries 5 deliberate "mm-hm"s during interviewer speech).
  4. Perceived naturalness 1-5 (owner, plus 2-4 other raters if available).

Tuning procedure (change ONE thing at a time, re-run a session)
  - Interruptions > target:
      a. Read prosodyPull / reason on the offending turns.
      b. If prosody said "finished" on mid-thought speech: raise the confident MIN by 100 ms
         (MOCK 300 -> 400) or lower PROSODY_WEIGHTS.sharpness 1.6 -> 1.3.
      c. If there was no prosody and it still interrupted: it is a gate/turn bug, not
         tuning -- write a failing sim trajectory from the log first.
  - p50 latency above target:
      a. Read largestStage. transcriptFinalMs -> authorizationReceivedMs large = classifier
         (check classifierSource hit rate) or the silence hold (check prosodyConfidence).
      b. quietOnsetMs -> transcriptFinalMs large = T_f; revisit P6 and client coalescing.
      c. authorizationReceivedMs -> firstSamplePlayedMs large = execution; check
         speechSource (cache misses?) and leading silence in renders.
  - Missed responses: always a defect; write a failing trajectory from the log.
Go / no-go
  GO when D1-D7 (section 1) hold across S1-S3. NO-GO with a written list of the failing
  metrics, the log evidence and the next change.

19. DELIBERATELY NOT BUILDING (AND WHY)
==========================================================================================

  - V6 continuers ("mm-hm" from the interviewer): the paper flags it as the one change that
    can make the product worse if tuned badly; it needs a persona amendment distinguishing a
    continuer from an acknowledgement. Revisit after P10 with the owner.
  - Full-duplex models (Moshi class): the gate architecture depends on discrete, authorized
    utterances.
  - Letting the realtime model decide when to speak: forbidden by I1.
  - Deciding on interim (unfinalized) transcripts: gate rule 2 stays. Speculation (P5) only
    precomputes the classification.
  - Switching to a newer "Live" model for capability: the paper's TTFA table shows newer is
    not faster (Gemini 3.1 Flash Live ~2.99 s vs 2.5 Flash native audio ~0.63 s). Any model
    change must be justified by measured TTFA, and with P3 most utterances no longer use the
    model's voice at all.

27. APPENDIX B -- FORMULAS
==========================================================================================

  Silence ramp (turn-completion.ts):
    ceiling(s) = 0.35                         if s <= min
               = 1                            if s >= settled
               = 0.35 + t * 0.65, t = (s - min) / (settled - min)   otherwise
    required(threshold) = min + ((threshold - 0.35) / 0.65) * (settled - min)

  Prosody:
    pull = confidence * (2 * probability - 1)                 in [-1, 1]
    pull > 0: min' = lerp(min, minConfident, pull); settled' = lerp(settled, settledConfident, pull)
    pull < 0: min' = lerp(min, minPatient, -pull);  settled' = lerp(settled, settledPatient, -pull)

  Required silence (ms):          clock      confident (pull=1)   patient (pull=-1)
    LEARNING (0.75, t=0.6154)     1938.5      465.4                2661.5
    MOCK     (0.80, t=0.6923)     2400.0      576.9                3307.7
    STRICT   (0.88, t=0.8154)     3667.7     1070.8                4793.8

  Clock-safe silence (P2.4):
    silenceAtFinal   = finalOccurredAt(client) - speechStoppedAt(client)
    silenceNow       = silenceAtFinal + (serverMonoNow - finalReceivedServerMono)
    wait             = required - silenceNow + 25

  Audio head: headBytes = floor(rate * 0.400) * 2   (24 kHz -> 19,200 bytes, ~26 KB base64)
  First-sample wall time: Date.now() + (startAt - ctx.currentTime) * 1000 + ctx.outputLatency * 1000
