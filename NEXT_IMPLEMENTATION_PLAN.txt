Implemented (resumption handle custody, correcting I04 item 2):
- The previous implementation accepted resumptionHandle in the realtime-token
  request body and forwarded it to the provider. That let any caller mint a
  credential that restores ANOTHER session's accumulated audio context —
  brief, probes and hints already spoken into it. Route ownership limited the
  blast radius to one account; it did not close it.
- apps/api/src/modules/realtime/resumption.ts: VoiceResumptionStore, an
  in-process TTL map keyed by session id. Deliberately not a database column:
  a handle is transport state with a lifetime of minutes, it is not interview
  evidence, and it must not enter the append-only log.
- New POST /interview-sessions/:id/voice-resumption is report-only; ownership
  is enforced by the existing module preHandler. The mint route no longer
  reads any handle from its request body and uses only what is stored for the
  session it is minting for. A failed mint clears the stored handle so a
  stale one cannot loop. An ended session clears it and refuses reports.
- Side effect worth having: continuity now survives a page refresh, because
  the handle no longer lives only in browser memory.
